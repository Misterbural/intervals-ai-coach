# Initial Intake

Principle: the intake establishes the athlete's profile, coaching language, environment, and season direction. Exact weekly time slots and volume are not locked here—they are decided at each block brief (`coach-block-brief`).

1. **Language first**: if `athlete-profile.md` does not yet specify a preferred language (or is missing), confirm the athlete's preferred coaching language immediately and conduct the entire intake—and all drafted files and workouts—in that language.
2. Read `endurance-methodology.md`, `coaching-journal.md`, `athlete-profile.md` (if present), and the active sport module(s) (`cycling.md`, `running.md`, `trail.md`, `swimming.md`, `triathlon.md`, `hyrox.md`, or custom) in the Project Library.
3. Analyze the last 3 months on intervals.icu: weekly volume and load by sport, current CTL/ATL/TSB, time-in-zone distribution, recent best efforts, and available wellness metrics (HRV, RHR, sleep). Summarize in 5 lines. If older activities are empty shells from Strava, flag it and use a backup connector if available. If returning from injury or layoff, explicitly note that older benchmarks do not represent current fitness.
4. Interview the athlete in short rounds (3–5 questions per message) across as many turns as needed; do not draft files until no major gaps remain. Cover:
   - **profile & gear** (if `athlete-profile.md` is missing or incomplete): age/weight, training background, sport mix & priority if practicing 2+ sports (primary + cross-training vs equal split), sensors/power meters/watch, direct sync sources;
   - **goals & horizon**: A/B/C races (or explicit lack of target race), dates, sport/format/vert, success criteria, process goals;
   - **health & injury context**: injury history, sensitive areas, medical/physio clearance and active restrictions if returning from injury;
   - **sport-specific environment & logistics** (ask only what fits the active sport modules):
     - *Trail*: local vertical gain access (daily vs weekends only vs flatlander), treadmill/stairs access, poles;
     - *Cycling*: local terrain (flat vs climbs), indoor trainer + fan/room temperature, virtual racing interest;
     - *Running*: track/road/trail/treadmill access, shoe rotation;
     - *Swimming / Triathlon*: pool length (25 m / 50 m), pool schedule/club, swim toys, open-water access, brick logistics;
     - *HYROX*: target division (Open / Pro / Doubles / Relay), access to a HYROX-equipped gym (sled + turf, Concept2 SkiErg & RowErg, sandbags, wall balls) vs standard gym substitutions, Concept2 ErgData sync, prior race splits or weak stations;
   - **season constraints & camps**: on-call weeks, travel, busy periods, or planned **training camps / vacation volume weeks**;
   - **strength & nutrition**: gym vs home equipment; daily cooking habits and constraints.
5. If no race is set, never invent one: propose a general endurance development period with no fixed race date.
6. Draft complete `athlete-profile.md` (if missing or needing updates) and `season-goals.md` in the athlete's preferred language. Present both for review; once approved, save them to the Project Library (or output the full files to upload).
7. If medical/physio clearance is still pending, state it clearly and pause—never build a block beforehand. Otherwise, offer to launch `coach-block-brief` for Block 1.
